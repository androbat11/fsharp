# Mission: F#

## Why
Learn F# for a work project: read the team's existing F# code, write backend/API code, and model business domains with types. Functional programming ideas are a second goal, with F# as the vehicle.

## Success looks like
- Read an unfamiliar F# file (records, unions, pipelines, pattern matching) and explain what it does
- Model a business domain with records and discriminated unions so invalid states can't be represented
- Build and run a small F# HTTP API
- Review a teammate's F# pull request with confidence

## Constraints
- Background is dynamic languages (Python/JS/Ruby); no static-typing or FP vocabulary assumed
- Sessions of 30-45 minutes, deeper mix of reading and exercises
- `dotnet` 8.0 installed locally (`dotnet fsi` available)

## Out of scope
- Computation-expression internals, type providers, and advanced type-level programming (for now)

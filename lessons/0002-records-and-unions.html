Records and unions

Lesson 2 · about 35 minutes · Mission: model business domains with types · builds on Lesson 1

The win

You can read a type declaration in F# and tell whether it means "all of these fields" (a record) or "one of these cases" (a union). You can also write a match over a union.

1. Records: a named bundle of fields

In Python you might pass a dict or a class instance around. An F# record is closer to a dataclass: named fields, each with a type. See the records reference.

type Customer = { Name: string; Age: int }

let ann = { Name = "Ann"; Age = 30 }
ann.Name        // "Ann"

Reading it: type declares a new type. Name: string means "a field called Name holding a string". When you build a value, the compiler matches the field names to the Customer type, so you don't write Customer(...).

Records are immutable (lesson 1). To "change" one, you copy it with with:

let older = { ann with Age = 31 }
// ann.Age is still 30; older.Age is 31

Predict: after let older = { ann with Age = 31 }, what is ann.Age?

Correct. with builds a new record and leaves the original alone.

2. Unions: one of several cases

A discriminated union (usually just "union") says a value is exactly one of a fixed list of cases. Each case can carry its own data. Reference: discriminated unions.

type PaymentMethod =
    | Cash
    | Card of number: string
    | Transfer of bank: string * account: string

Each line starting with | is a case. Cash carries nothing. Card of number: string carries one string. * here separates two pieces of data (it is not multiplication). In Python you'd probably use a string like "cash" plus optional fields and hope nobody mixes them up. Here a Card can't accidentally have a bank.

let pay = Card "1234567812345678"

Choose: a shape is either a Circle or a Square. Which F# construct models that?

Correct. "Either/or" is a union. "Both/and" (a customer has a name and an age) is a record.

3. match: take a union apart

let describe payment =
    match payment with
    | Cash -> "paid in cash"
    | Card number -> "card ending " + number.Substring(number.Length - 4)
    | Transfer (bank, _) -> "transfer via " + bank

match ... with tests the value against each pattern, top to bottom, and returns the result of the first that fits. A pattern like Card number also names the data inside the case so you can use it. _ means "there's something here, I don't care what". This is like a much stricter if/elif chain (pattern matching).

I ran these in dotnet fsi: describe Cash gives "paid in cash", and describe (Transfer ("BHD", "999")) gives "transfer via BHD".

Predict: what does describe (Transfer ("BHD", "999")) return?

Correct. The pattern Transfer (bank, _) binds bank to "BHD" and ignores the account.

4. Why this matters: the compiler checks every case

If you leave a case out, F# warns you. I tried a match with only Cash and Card _ and got:

warning FS0025: Incomplete pattern matches on this expression.
For example, the value 'Transfer (_, _)' may indicate a case not covered

Now add a new payment type to the union and the compiler points at every match that needs updating. This is the main reason teams use unions to model business rules.

Recall: what happens when a match forgets one union case?

Correct. You find out while compiling, before the code runs.

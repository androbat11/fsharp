Reading an F# pipeline

Lesson 1 · about 30 minutes · Mission: read your team's F# code

The win

By the end you can look at a typical F# function built from let and |> and say what it returns, without running it.

1. let binds a name, and the value never changes

In Python, x = 5 can be followed by x = 6. In F#, let x = 5 gives x a value for good. There are no statements; everything is an expression that produces a value. See the tour of F#.

let add x y = x + y     // a function of two arguments
let double n = n * 2

No def, no return, no parentheses or commas. The last expression is the result. Types are inferred: the compiler knows add works on numbers even though you never wrote that.

2. Calling a function is just a space

add 3 4        // 7

Giving a function fewer arguments than it needs gives back a new function (partial application):

let addTen = add 10
addTen 5       // 15

Recall: with the definitions above, what is addTen 5?

Correct. add 10 waits for its second argument: 10 + 5.

3. The pipeline |>

x |> f means "pass x to f". It lets you read data flowing top to bottom, like a shell pipe or a method chain in JS.

let result =
    [1; 2; 3; 4; 5; 6]
    |> List.filter (fun n -> n % 2 = 0)
    |> List.map double
    |> List.sum

Read it as steps: start with the list, keep the evens, double each, add them up. fun n -> ... is an inline lambda, like lambda n: .... Lists use ; between items. List.filter, List.map and List.sum come from the List module.

Recall: what does x |> f mean?

Correct. The pipe just flips the order: f x becomes x |> f.

Predict: what does the pipeline result above evaluate to?

Correct. Evens: 2, 4, 6. Doubled: 4, 8, 12. Sum: 24.

Try it yourself

Run dotnet fsi, paste the code, and end each statement with ;;. Then change the filter to keep numbers greater than 3 and predict the result before you run it.
